## v1.16.0 · 2026-10-05 —— Windows 版首发

### 新增
- **Windows 版**（仓库里的 `AnkiAssistant\`）：与安卓版功能对齐的桌面程序 —— AI 制卡、浏览与本地草稿、
  输出格式（可自定义字段、默认牌组、标签与学科背景）、五套皮肤（含深色）、头像、更新日志与检查更新
- **安装程序**（`AnkiAssistantSetup\`）：每用户安装（不弹 UAC），登记开始菜单/桌面快捷方式与卸载项，
  支持 `--silent` 静默安装、`--uninstall` 卸载、`--tray` 开机自启
- 仓库重组为三个目录：`AnkiAssistant`（Windows 版）、`AnkiAssistantAndroid`（安卓版）、
  `AnkiAssistantSetup`（安装器）；根 `README.md` 重写，并新增 `GITHUB_SETUP.md`

### 改
- Windows 版通过 **AnkiConnect** 与本机 Anki 桌面端通信（需要 AnkiConnect 插件 `2055492159`），
  不直接读写收藏库文件；安卓版仍是内置引擎，两者数据经 AnkiWeb 同步保持一致
- 两端共用同一个版本号，一个 Release 同时发布 `AnkiAssistant-Setup.exe` 与
  `AnkiAssistantAndroid\AnkiAssistant.apk`

### 修
- **内置「英语词汇」格式的「例句」字段永远是空的**：AI 返回的 JSON 里有 `example`，
  但解析只保留 6 个规范键（音标/词性/定义/公式/易混/中文），其余键被丢掉。
  现在额外键会原样透传（规范键仍优先），自定义格式里的任何字段都能拿到值

## v1.12.0 · 2026-10-03 —— 浏览页重写（适配任意笔记类型）、公式渲染修好、旧卡转换

### 浏览页从头重写
- **不再假设任何字段名**：卡片可能来自任意笔记类型（自己建的、电脑上建的、别人分享的）
  - 列表标题取「第一个有内容的字段」，副标题显示笔记类型与标签
  - 详情把该笔记的**所有字段**按顺序原样列出，空字段自动隐藏
- **详情复用制卡页预览的渲染管线**（同一个编辑器页面、同一套字段样式与 MathJax 配置），
  所以字体、字号、行距、公式渲染与预览完全一致
- 删掉两个没用的按钮：
  - 「在电脑上编辑」——早已没有电脑端（AnkiConnect 时代的东西）
  - 「同步到云端」——同步就在左上角头像里，页面上再放一个只会让人困惑
- 段落切换改成扁平分段控件，页面顶部补上留白（之前紧贴顶栏很难看）

### 修：公式显示不出来 / 字形空白
- 详情页此前用 `loadDataWithBaseURL` 渲染，页面是**匿名来源**，WebView 会挡掉 MathJax 的字体请求，
  于是公式只有空白占位。现在改由本机资源服务器以 http 输出（同一来源），字体正常加载
- 修掉一次界面**持续抖动**：详情改成 `loadUrl` 后 `onPageFinished` 又触发一次渲染，
  形成 loadUrl→onPageFinished→loadUrl 的无限重载；现在只在页面就绪后注入一次
- 老卡里 `\(A\),\quad \(B\)` 这种被切断的写法，`\quad` 落在数学环境外面只会当普通文字。

## v1.11.0 · 2026-10-03 —— 修好 AnkiWeb 同步；三个内置输出格式；设置页左索引

### 修：同步报 400「missing original size」
- **根因**：AnkiWeb 会把部分账号迁到别的同步节点（本账号被迁到 `https://sync2.ankiweb.net/`，
  服务端以 **308 重定向**告知）。之前的实现忽略了这个新端点，后续请求仍打到老节点，
  老节点对 `download` 回 **303**，客户端拿到非 zstd 响应 → 400 missing original size。
- **修法**：把服务器返回的 `newEndpoint` 记下来并**用于之后所有请求**（登录/状态/同步/媒体），
  同时持久化到本机，避免每次重新跳转。全量同步还补上了 `serverUsn`
  （取自 `syncCollection` 响应的 `serverMediaUsn`，AnkiDroid 也是这么做的）。
- **实测**：设备上 `SYNCREAL PASS`，全量下载 + 媒体同步成功，
  之后浏览页读到云端真实数据：6 个牌组、13 张卡片（`A Level Physics`、`A Level Pure Mathematics` …）

  - APK 里只有 AES-GCM 密文，没有明文；密钥由「口令 + 随机 salt」经 PBKDF2-HMAC-SHA256（12000 轮）派生
  - 口令不写成完整串，拆成 4 段放在不同方法里，其中一段反序存放 —— 直接 `strings` 扫 APK 拿不到
  - 生成/更换方式：`java tools/MakeSecret.java <新Key> <新口令>`，把输出的三行粘进 `Secret.java`
- **手填优先**：设置里填过的 Key 优先于内置 Key（`Store.aiApiKeyFor`），
  发现异常随时在设置里换一把，不用重新发版
- 设置页 AI Key 输入框的提示改为「留空则用内置 Key」

### 安全说明（必须知道）
- 只要密钥随 APK 分发，**一定能被逆向出来**；加密只是把「随手提取」提高到「需要真正逆向」
- 因此**故意的取舍**：仓库/Release 是公开的，所以
  1. 只内置了智谱这把**免费档** Key；付费余额的 Key（如 DeepSeek）**不打包**，
     要加就用上面那条命令单独生成（泄露代价由你自己权衡）
  2. 智谱后台随时可以**吊销/重建**这把 Key：换完重新生成密文、发个新版即可
  3. 真要做到"完全不可提取"，只能把 Key 放在自己的服务端做代理转发（本项目不走这条路）
